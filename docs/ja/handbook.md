# Cls-Studio ハンドブック — ゼロから最初の検査まで

> 英語版: [../handbook.md](../handbook.md)

上から順に一度たどれば全体がつかめる導入ガイドです。2 回目以降は画面別リファレンスの [ユーザーガイド](user-guide.md) が早道です。

## 1. インストールと起動

ソース zip をダウンロードして(Releases ページ、または **Code → Download ZIP**)展開します — git は不要です。あとは展開したフォルダ直下で:

**Windows** — `install-windows.bat` をダブルクリック → 続けて `start-windows.bat` をダブルクリック。インストーラーは GPU を自動判定し(`cpu` / `cuda124` 引数で上書き可)、起動スクリプトは準備完了後にブラウザで UI を開きます。

**macOS:**
```bash
bash install-macos.sh
bash start-macos.sh
```

ブラウザで **http://localhost:8791/ui/** を開きます。ヘッダーで日本語/英語を切り替えられます。停止は `stop-windows.bat` / `bash stop-macos.sh` です。

GPU がない場合もすべて CPU で動作します(大きなバンクでは教示・採点が遅くなります)。

## 2. プロジェクトとバンクを作る

1. **プロジェクト**画面でプロジェクトを作成します。製品 × カメラ構成ごとに 1 つが目安です。
2. プロジェクトはメモリバンクを 1 つ持ちます。1 ラインで複数品種を流すなら、品種ごとにプロジェクトを分けてください — しきい値・判定レシピ・書き出しはすべてバンクに属します。

## 3. バンクを作る

プロジェクトの**バンク**タブを開きます。番号付きの 3 ステップで、終わるごとに ✓ が付きます。

1. 良品画像を数十枚**インポート**します。1 枚につき 1 回だけエンコーダを通してパッチを保存します — 1 枚数秒、そして二度と払いません。
2. **ラベル**を付けます。リストを順に見て、正常 / 不良(種類つき: 「傷」「焦げ」など)/ 過検知抑制 のどれかを与えます。特徴は動かないので、ラベルは何度でも変えられます。
3. **バンクを組み立てる**。ラベルだけでは検査は変わりません — 組み立てが反映の操作です。

枚数より**カバレッジ**が重要です: ロット差・照明の揺らぎ・位置ずれなど、想定される正常のばらつきを含めてください。同じ見た目の数百枚より、多様な数十枚が効きます。

ラインカメラの TIFF はそのまま使えます(プレビューは自動変換)。

**不良品画像があれば**、種類つきの**不良**を付け、1 枚開いて**欠陥をマーク**から実際の欠陥部分に矩形を描いてください — その部分のパッチが**欠陥見本**になり、後の検出が鋭くなります。NG は任意で、ゼロでも開始できます。

## 4. 分離度評価を実行する

**学習**タブで評価スイープを実行します。バンク内の全画像がバンクに対して採点され(自分自身のパッチは除外されるので、良品が自明に一致することはありません)、OK / NG のスコア分布が並んで表示されます。画像がロット単位で来るなら、**検証**を 1 枚除外ではなくロットごと除外に設定してください — 同一ロットの双子画像が残っていると精度が甘く出ます。

- **分布がよく分かれている** — 提案されたしきい値を採用し、保存すれば完了です(検査タブの**判定設定を保存**)。
- **重なっている** — 多くはカバレッジ不足です。重なっている OK 画像が示す種類の正常ばらつきを追加で教えるか、NG 画像に欠陥矩形をマークして α 項を効かせ、再スイープしてください。

k(近傍数)と α(見本の重み)はスイープ後に自動調整されます。手動でも動かせて、分布の変化をその場で確認できます。

保存した判定レシピはバンク内容に対して刻印されます。その後バンクが変わるとレシピに「要再確認」の警告が付きます。

## 5. 検査する

**検査**タブに切り替えて画像をドロップします(複数可):

- 各画像にスコア、しきい値に対する OK / NG 判定、ヒートマップが付きます。ヒートマップは絶対スケール — どの画像でも同じ色は同じスコアで、しきい値が色の基準点です。
- アトリビューションパネルには、既知の欠陥ラベルそれぞれへの「似ている度合い」が出ます。
- 結果はサーバー側に保存され(デフォルトでプロジェクト毎 200 件)、リロード後も復元されます。

## 6. 教え続ける — 修正ループ

Cls-Studio を現場で育てる中核の習慣です:

- **過検出**(OK を NG と判定): その画像を OK として教えます。特定の無害なパターンが繰り返し反応するなら **negative** 層に追加すると、その近傍の反応が抑えられます。
- **見逃し**(NG を OK と判定): ラベルを付けて critical に教え、欠陥矩形をマークします。

どちらも追記のみで、次の 1 枚から反映されます。既存の記憶が壊れることはありません。大きめの修正をした後は分離度評価を再実行してしきい値を確認・再保存してください。

## 7. バンク — またはプロジェクト丸ごと — を別マシンへ移す

バンクは `.clsbank.zip` 1 ファイルに書き出せます — 特徴・見本マーク・サムネイル・判定レシピが同梱され、別の Cls-Studio に読み込めば同一の検査ができます。

**プロジェクトのすべて**(全バンク・教示画像・検査ログ)を移すなら、プロジェクトパッケージを使います: プロジェクトカードの書き出しボタンが `.clsproj.zip` 1 ファイルを書き出し、読み込むと同一内容の新しいプロジェクトが作られます。詳細は [インポート/エクスポート](import_export.md)へ。
